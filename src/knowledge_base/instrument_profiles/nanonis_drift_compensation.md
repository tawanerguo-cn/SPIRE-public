# 漂移补偿

## 先判断漂移

停在固定 XY，保持偏压、设定电流和反馈不变，避开 pulse、poke、进退针后的恢复段，再看 Z 随时间的趋势。
扫描地形、反馈变化和压电蠕变也会改变 Z，不能都归因于温漂；Z 漂移也不能代替 X/Y 漂移测量。

## 怎样用

- 人工入口：**Modules → Piezo Calibration → Drift Compensation**。页面显示开关、Vx/Vy/Vz 和各轴饱和状态。
- 先核对坐标方向与补偿符号，再设速度；特征在图上的移动速度不能直接照填。1 pm/s = 1e-12 m/s，1 nm/s = 1e-9 m/s。
- 本站 Z 补偿用法：观察漂移，施加补偿，再看 Z 是否基本不漂；同时检查电流和饱和状态。
- 补偿后用新的稳定窗口复测残余漂移。条件变了就重新估计，不把前一次速度一直沿用。

## 容易混淆的操作

Atom Tracking 的 Drift measurement 用来测漂移；Apply drift correction 会叠加补偿速度。
Quick Operation 会启动调制、跟踪、测量和补偿，不只是打开窗口。

补偿是持续状态，关闭窗口或断开 Python 连接不会停止它。结束时读回确认关闭；
“速度为零”和“补偿已关闭”分别核对。

本站自动 Z 补偿仍待温度上下文和现场验证，目前先做只读分析。人工用法不依赖这项自动化是否完成。
接口支持范围与调用方法见[控制说明](../../../docs/operations/authorized-control.md#漂移补偿)。

## 协议回读与错误后的状态

一次历史站点协议核对采用七个数值字段加尾部错误/状态值的返回形状。若把尾部状态误解析成第八个数值字段，就可能凭空得到零饱和阈值；缺失或未被协议明确定义的字段应保留为 unknown。该站点的 `Util.VersionGet` 不可用，所以对应 Nanonis 的确切发行版本未知；不要把这一返回形状推广到未经核对的版本。

该站点一次 drift-toggle 请求在 Z 控制开启时被拒绝，但后续记录没有解决实际状态。协议报错不能证明所有字段都没有副作用。出现错误后应独立读取补偿 enable 状态和各轴设置，再决定后续动作；不要盲目重发，也不要从这次拒绝推出通用的 Z 反馈前置条件或“关闭反馈即可”的工作规程。这是版本未知的单站观察，尚未作为普遍设备行为验收。
